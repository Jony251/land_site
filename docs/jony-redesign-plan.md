# Jony Redesign Plan — land_site

Автор: Jony (дизайн/фронтенд-агент). Бриф-источник: `docs/portfolio-strategy.md`
(включая раздел 9 про AI-услугу). Дата: 2026-09-22.

Статус: план и реализация выполнены в одну итерацию (см. раздел "Что сделано").
Документ фиксирует решения постфактум, чтобы будущие агенты/владелец понимали
логику изменений без чтения диффов.

---

## 1. Визуальное направление

**Диагноз:** сайт выглядел "студенческим" из-за (а) пустой заставки без
контента на Home, (б) плоской сетки проектов без иерархии, (в) разрозненных
инлайн-стилей вместо единой системы токенов.

**Решение:** ввести единый набор design-токенов в `pages/colors.css`
(`--bg`, `--surface`, `--text`, `--muted`, `--border`, `--accent`, `--radius`,
`--shadow*`) и построить на них переиспользуемые примитивы в `App.css`:
`.hero`, `.btn`/`.btn.primary`, `.card-grid`/`.card-link`. Это заменяет
инфантильную заставку "C.A.T." на структурный, предсказуемый layout,
типичный для профессиональных студийных сайтов.

**Бренд "C.A.T."/кот:** не убран полностью — приглушён до детали бренда.
Гифка кота теперь маленький акцент внутри eyebrow-бейджа на Home
(`home-eyebrow-mark`, 22×22px), а не главный визуальный элемент экрана.
Решение: сохранить индивидуальность, но не дать ей конкурировать с оффером
и флагманским кейсом за внимание.

**Типографика/сетка:** `clamp()`-заголовки (h1/h2) для плавного масштабирования,
единый `--radius: 14px` на карточках, `--shadow-lg` для приподнятых hero-карточек.

## 2. Home

- Hero: eyebrow-бейдж → заголовок-оффер (`home.title`) → подзаголовок с AI-фразой
  (`home.subtitle`) → два CTA (`Начать проект` / `Портфолио`).
- Рядом с копирайтом — карточка флагманского проекта (`home-flagship-card`,
  берётся из `projects.filter(p => p.tier === 'flagship')[0]`, сейчас это
  `pet-project-crm`) как визуальное доказательство "с порога".
- Секция "Что мы строим" — зеркалит 5 уровней Services (`SERVICE_KEYS`,
  включая `s5` = AI-интеграции), кликабельна на `/services`.
- Секция "Доказательства, а не обещания" — карточки всех flagship-проектов
  (сейчас `pet-project-crm` + `aispace`) с бейджем уровня и CTA на `/works`.

## 3. Works — иерархия

- В `projectsData.js` каждому проекту добавлено поле `tier`:
  `flagship` (pet-project-crm, aispace) / `product` (crossplatform, landfolio,
  change-web) / `craft` (android, cross_II, learning, massage).
- `Works.jsx`: фильтр вместо WEB/ANDROID теперь `all/flagship/product/craft`
  (`works.filters.*`), список сортируется так, что flagship всегда первыми.
- `Works.css`: `.project-card.tier-flagship` занимает 2 колонки грида и получает
  более высокое превью (320px vs 200px) — визуальный вес, а не только текстовый
  бейдж.
- Критерий деления (из брифа Ciri, раздел 3): наличие состояния/ролей/
  собственного бэкенда и БД — не "сколько файлов в репозитории".

## 4. Страница кейса (`InWork.jsx`)

- Добавлен блок `caseKeys` (Проблема → Решение → Стек → Результат) — рендерится
  только если у проекта есть `caseKeys` в `projectsData.js`. Сейчас заполнено
  для `pet-project-crm` и `aispace` (тексты — из раздела 4 брифа Ciri,
  без выдуманных метрик).
- Остальные (product/craft) проектов кейс-блок не показывают — у них его
  намеренно нет, чтобы не размывать формат "полноценный кейс" на простые
  лендинги.
- Добавлен `inwork-tier-badge` рядом с заголовком.

**Coin Collector System (coin_set + coinset-api) сознательно НЕ добавлен** —
как и зафиксировано в открытых вопросах брифа Ciri, у обоих репозиториев нет
README/скриншотов. Добавлять его сейчас значило бы либо выдумывать
визуальные материалы, либо давать пустой кейс — оба варианта хуже, чем
подождать материалы от владельца.

## 5. Services (`Info.comp.jsx`)

Добавлен 5-й уровень `s5` = "AI-интеграции" поверх существующих четырёх
(Landing / Ongoing Support / Updates & Upgrades / Backend & API). Раскладка
`services-grid` — `auto-fit`, дополнительная карточка не ломает сетку.
Текст `s5` явно рамочит это как **компетенцию** (proof: AI Space, TG_bot,
CalendarBot из брифа), а не как готовый клиентский кейс.

## 6. About

Добавлен параграф `about.range` — прямое утверждение диапазона (от лендинга
до CRM с БД) плюс AI-фраза, без цифр/метрик, которых нет.

## 7. Motion / a11y

Никаких новых анимаций, конфликтующих с `prefers-reduced-motion`, не введено:
переходы ограничены `transform`/`box-shadow` на hover (уже покрыты глобальным
`html[data-reduce-motion="true"]`-оверрайдом и медиа-запросом в `index.css`).
`AccessibilityWidget`/`src/a11y/*` не тронуты.

## 8. i18n

Новые ключи добавлены консистентно в `en`/`ru`/`he` (`translations.js`):
`home.*` (eyebrow, title, subtitle, cta*, flagship*, capabilities*, featured*),
`works.filters.*`, `works.tier.*`, `works.case.*`, `works.projects.crm.case.*`,
`works.projects.aispace.case.*`, `services.s5.*`, `about.range`. HE-переводы —
не машинный дословный перевод, тексты адаптированы под RTL-чтение.

**Исправлено в этой сессии:** `home.capabilitiesLead` во всех трёх языках
говорил "четыре уровня" — обновлено на "пять" (EN/RU/HE), так как Services
теперь имеет 5 уровней после добавления AI-интеграций.

  `services.s5` достаточно.

  деплоем — эта сессия проверяла только сборку/линт, не рендер в браузере.
