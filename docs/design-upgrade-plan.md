## 1. Строка "Технологии / Виды работ" в кейсе

**Файлы:** `src/pages/in_Work/InWork.jsx`, `src/pages/in_Work/InWork.css`,
`src/pages/in_Work/projectsData.js`, `src/i18n/translations.js`.

**Проблема сейчас.** В `InWork.jsx` (строки 75-86) технологии уже рендерятся
как pill-теги (`.inwork-technologies` / `.inwork-tech-tag`), но **без заголовка-
лейбла** — просто плавающий ряд иконок. У koptelnya сила приёма именно в явном
текстовом лейбле "Технологии:" / "Виды работ:" — это тоже нужно исправить,
это не только добавление нового поля, но и подпись к уже существующему.

**Что добавить:**

## 2. Счётчики в фильтрах Works

**Файлы:** `src/pages/Works.jsx` только (i18n трогать не нужно).

**Что менять.** Сейчас (строки 36-47) лейбл кнопки фильтра — чистый
`t(\`works.filters.${tierKey}\`)`. Посчитать количество проектов на каждый
таб и подставить рядом с текстом, **не трогая переводы** (простое `({count})`
работает одинаково на EN/RU/HE — это цифры и скобки, не требуют локализации,
корректно отображаются и в RTL благодаря Unicode bidi-алгоритму):

```jsx
{['all', ...TIER_ORDER].map((tierKey) => {
  const count = tierKey === 'all'
    ? projects.length
    : projects.filter((p) => p.tier === tierKey).length;
  return (
    <button
      key={tierKey}
      type="button"
      className={`works-category ${selectedTier === tierKey ? 'active' : ''}`}
      onClick={() => setSelectedTier(tierKey)}
    >
      {t(`works.filters.${tierKey}`)} <span className="works-category-count">({count})</span>
    </button>
  );
})}
```

**CSS** (`Works.css`): `.works-category-count { opacity: 0.55; font-weight: 400; }`
— чуть приглушить счётчик, чтобы не спорил по весу с активным лейблом.

**Не нужно** менять `works.filters.*` в translations.js — количество не часть
перевода, а вычисляемое значение.

## 3. Акцентное слово в заголовке Home + декоративная сетка

### 3a. Акцентное слово

**Файлы:** `src/pages/Home.jsx`, `src/i18n/translations.js`, `src/pages/Home.css`
(по желанию — стиль span).

**Проблема:** `<h1>{t('home.title')}</h1>` — одна строка без акцента.

**Решение:** разбить `home.title` на три ключа: `home.titleStart`,
`home.titleAccent`, `home.titleEnd`. Слово-акцент — **"systems"/"системы"/
"מערכות"** (совпадает с позиционированием "инженер, который строит системы",
не просто "trust" — это уже вторая часть заголовка про то, ЧТО мы строим).
Проверено построчной сверкой — конкатенация Start+Accent+End даёт **точно**
текущий текст (ничего не меняется по смыслу, только разбивка):

```
en:
  titleStart: 'We build sites people trust — and '
  titleAccent: 'systems'
  titleEnd: ' businesses run on.'
ru:
  titleStart: 'Строим сайты, которым доверяют — и '
  titleAccent: 'системы'
  titleEnd: ', на которых держится бизнес.'
he:
  titleStart: 'בונים אתרים שסומכים עליהם — ו'
  titleAccent: 'מערכות'
  titleEnd: ' שהעסק שלכם רץ עליהן.'
```

(В HE союз "ו" — "и" — приклеен к акцентному слову без пробела, это нормальная
орфография иврита, не опечатка — сохранить именно так.)

`Home.jsx`, заменить `<h1>{t('home.title')}</h1>` на:
```jsx
<h1>
  {t('home.titleStart')}
  <span className="home-title-accent">{t('home.titleAccent')}</span>
  {t('home.titleEnd')}
</h1>
```

`Home.css`: `.home-title-accent { color: var(--accent); }` — минимум, можно
чуть плотнее начертание (`font-weight: 800` если базовый h1 легче), но не
добавлять анимаций/подчёркиваний — сайт уже избегает лишнего движения ради
`prefers-reduced-motion`.

Удалить старый ключ `home.title` после переноса (или оставить неиспользуемым —
предпочтительно удалить, чтобы не путать будущих редакторов).

### 3b. "Обнажённая" сетка (декоративный приём)

**Файлы:** `src/App.css` (или `Home.css`/`Info.comp.css` — где заводить,
решает Джон по месту), никаких новых i18n-ключей.

**Идея (из design-research, п.5):** тонкие вертикальные разделители между
карточками в `.card-grid` (уже используется на Home "Что мы строим" и в
Services) — визуальная метафора "структура видна, а не спрятана", подходит
позиционированию инженера лучше декоративных элементов.

**Реализация:** не через реальные бордеры между колонками грида (ломаются на
разном числе колонок в `auto-fit`), а через `background-image:
repeating-linear-gradient(90deg, transparent, transparent Npx, var(--border)
Npx, var(--border) (N+1)px)` на контейнере `.card-grid`, ИЛИ проще и надёжнее —
`border-left: 1px solid var(--border)` на `.card-link:not(:first-child)` при
`grid-auto-flow: row` с фиксированным числом колонок на десктопе. **Обязательно**
убрать/скрыть на мобильной раскладке (`@media (max-width: 720px)`), где карточки
в один столбец — вертикальные разделители там не нужны и в RTL-раскладке
превратятся в визуальный шум. Проверить на HE (RTL) — разделители должны
логически остаться "между" карточками независимо от направления (использовать
`border-inline-start`, а не `border-left`, — это уже RTL-safe по спецификации
CSS Logical Properties, предпочтительно перед добавлением отдельных
`html[dir="rtl"]` переопределений).

Это низкоприоритетный декоративный пункт — если оценка по месту покажет, что
разделители визуально спорят с уже существующими `--shadow`/`--border` на
карточках `card-link`, лучше не форсировать и пропустить только 3b, оставив 1/2/3a.

## 4. (Дополнительно, моя рекомендация) Мягкая версия "боль → снятие боли"

**Обоснование.** В design-research (раздел 5, "новые взгляды") я предложила

запрета, а одна спокойная фраза, снимающая типичный страх клиента ("сайт

напрямую усиливает уже существующий `services.s2` (Ongoing Support), поэтому
добавляю в план как быстрый выигрыш, а не как отдельную инициативу.

**Что добавить:** новый ключ `services.lead`, рендерится как `<p>` сразу под
`<h2>{t('services.title')}</h2>` в `Info.comp.jsx` (сейчас там сразу идёт
`.services-grid` без подводки).

```
en: "Not just a site that looks good — a system that keeps working after handover."
ru: "Не просто сайт, который красиво выглядит, а система, которая продолжает работать после сдачи проекта."
```
